# Запуск VacationHunter вне песочницы

Этот способ запускает сервер непосредственно на вашем Windows-компьютере и даёт ему обычный сетевой доступ вашей системы. Все команды ниже нужно вводить в **Windows Terminal / PowerShell**, а не в адресную строку браузера, DevTools или терминал защищённой среды Codex.

## 1. Проверить инструменты

Нужен Node.js 20 или новее. Откройте новое окно PowerShell и выполните:

```powershell
node --version
corepack --version
git --version
```

Версия Node должна начинаться с `v20` или быть новее. Если `node` не найден, установите актуальную LTS-версию с <https://nodejs.org/> и заново откройте PowerShell.

## 2. Перейти в проект

Если репозиторий уже находится в текущем месте:

```powershell
Set-Location 'C:\Users\drumi\OneDrive\Документы\VacantionHunter'
```

Для чистой установки на другом компьютере:

```powershell
git clone https://github.com/Drumikk/VacantionHunter.git
Set-Location .\VacantionHunter
```

Проверить, что открыта правильная папка:

```powershell
Get-Location
Get-Content .\package.json -TotalCount 5
```

## 3. Установить зависимости

Проект зафиксирован на pnpm 11.9.0:

```powershell
corepack enable
corepack prepare pnpm@11.9.0 --activate
pnpm install --frozen-lockfile
```

Если PowerShell запрещает запуск `pnpm.ps1`, используйте исполняемый файл напрямую:

```powershell
pnpm.cmd install --frozen-lockfile
```

## 4. Создать локальную конфигурацию

Скопируйте шаблон. Реальный `.env` исключён из git:

```powershell
Copy-Item .\.env.example .\.env
notepad .\.env
```

Минимальная конфигурация для живого поиска:

```dotenv
HOST=127.0.0.1
PORT=4173
ENABLE_LIVE_SOURCES=true
ENABLE_DEMO_SOURCE=false
SOURCE_CONCURRENCY=16
REQUEST_TIMEOUT_MS=8000
ATS_REQUEST_TIMEOUT_MS=30000
```

Большая часть публичных API, RSS и ATS-досок работает без ключей. Остальные коннекторы останутся в статусе «Нужна настройка» и не помешают поиску. Заполняйте только полученные вами credentials, например:

```dotenv
JOOBLE_API_KEY=ваш_ключ
USAJOBS_API_KEY=ваш_ключ
USAJOBS_EMAIL=email_указанный_при_получении_ключа
```

Не вставляйте реальные токены в чат, коммиты или `config/sources.json`. После любого изменения `.env` сервер нужно перезапустить.

## 5. Проверить и запустить

```powershell
pnpm test
pnpm start
```

Не закрывайте это окно PowerShell: в нём работает сервер и выводятся ошибки коннекторов. Откройте в браузере:

<http://127.0.0.1:4173/>

Для разработки с автоматическим перезапуском после изменения файлов:

```powershell
pnpm dev
```

Остановить сервер можно сочетанием `Ctrl+C`.

## 6. Как работает новый потоковый поиск

При нажатии «Найти вакансии» интерфейс сначала мгновенно показывает совпадения из локального хранилища. Если включено «Обновить данные из источников», сервер параллельно опрашивает источники и отправляет в браузер NDJSON-события через `POST /api/search/stream`:

1. `initial` — локальная выдача без ожидания сети;
2. `progress` — завершение очередного источника и, при наличии новых вакансий, обновлённая выдача;
3. `done` — итоговый снимок и полный отчёт.

Повторный поиск отменяет предыдущий поток. Уже начавшиеся HTTP-запросы отдельных коннекторов могут корректно завершиться, но новые источники старого поиска больше не запускаются. Общий обход большого каталога всё ещё может занимать время; пользователь больше не ждёт его завершения, чтобы увидеть первые результаты.

Для мгновенного поиска только по уже загруженной базе снимите флажок «Обновить данные из источников».

## 7. Проверить доступ в интернет

Сначала проверьте DNS и HTTPS из того же окна PowerShell, где будет запущен сервер:

```powershell
Resolve-DnsName www.arbeitnow.com
Test-NetConnection www.arbeitnow.com -Port 443
(Invoke-WebRequest -Uri 'https://www.arbeitnow.com/api/job-board-api' -TimeoutSec 20).StatusCode
```

Ожидается `TcpTestSucceeded : True` и HTTP-статус `200`. Затем можно проверить один публичный коннектор без запуска браузера:

```powershell
pnpm smoke:live -- --source=arbeitnow "software engineer remote"
```

Проверка самого локального сервера во втором окне PowerShell:

```powershell
Invoke-RestMethod 'http://127.0.0.1:4173/api/health' | Select-Object ok, jobs
```

Если из обычного PowerShell сеть работает, а в запуске из Codex появляется `fetch failed`, запускайте приложение именно этой инструкцией на хосте. Это ограничение окружения запуска, а не доказательство поломки источника.

## 8. Если внешние источники не отвечают

- `fetch failed`, ошибка DNS или `TcpTestSucceeded : False`: проверьте VPN, корпоративный proxy, антивирус, firewall и доступ Node.js к исходящему HTTPS на порт 443.
- `401` или `403`: проверьте ключ, email/User-Agent и правила конкретного API. Вход в сайт через браузер не авторизует серверный API автоматически.
- `429`: источник исчерпал квоту. VacationHunter поставит его на cooldown и повторит позже; не увеличивайте `SOURCE_CONCURRENCY`.
- `cloudflare_challenge`, CAPTCHA или login wall: приложение не обходит защиту. Нужен официальный API, RSS, email-feed или партнёрский доступ.
- Первый полный проход слишком тяжёлый: временно задайте `SOURCE_CONCURRENCY=8`, уменьшите ATS-реестр или ищите без флажка обновления.
- Порт занят: задайте, например, `PORT=4174` в `.env` и откройте `http://127.0.0.1:4174/`.

Статусы и официальные ссылки регистрации доступны по кнопке «Источники» в верхней панели. Значения секретов сервер в браузер не отправляет.

## 9. Быстрый офлайн-режим

Чтобы проверить интерфейс без внешней сети:

```powershell
$env:ENABLE_LIVE_SOURCES='false'
pnpm start
```

Переменная, заданная так, действует только в текущем окне PowerShell. Для постоянной настройки измените `.env`.
